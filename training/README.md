# Thrones training pipeline

Reproducible LoRA fine-tuning of **Qwen3.5 4B** into a *Thrones adapter*. The base model is never modified; the adapter is a separate file that llama.cpp applies at load time (`llama-server --lora`).

Policy and rationale: [`docs/TRAINING_PLAN.md`](../docs/TRAINING_PLAN.md). Results: [`runs/thrones-adapter-0.1/MODEL_CARD.md`](runs/thrones-adapter-0.1/MODEL_CARD.md).

## Environment (Windows, RTX 50-series)

Separate from the app's `.venv`, all caches on D:.

```powershell
uv venv --python 3.12 .venv-train
uv pip install --python .venv-train\Scripts\python.exe torch==2.14.1 torchvision --index-url https://download.pytorch.org/whl/cu130
uv pip install --python .venv-train\Scripts\python.exe unsloth datasets sacrebleu --constraint torch-pin.txt --extra-index-url https://download.pytorch.org/whl/cu130 --index-strategy unsafe-best-match
uv pip install --python .venv-train\Scripts\python.exe .\runtime\llama.cpp-src\gguf-py
```

Tested versions: torch 2.14.1+cu130, transformers 5.17.0, trl 1.15.0, peft 0.21.2, unsloth 2026.11.4, gguf 0.19.0 (llama.cpp b12289).

Base weights: the official `Qwen/Qwen3.5-4B` safetensors (8.7 GB) in `training/base/Qwen3.5-4B/` (not committed; file sizes verified against Hugging Face).

## Steps

```powershell
$env:HF_HOME = "D:\Thrones\.cache\hf"
.venv-train\Scripts\python training\build_dataset.py                       # 1. data  (~1 min)
.venv-train\Scripts\python training\train_lora.py --run thrones-adapter-0.1   # 2. train (~37 min on RTX 5060 Ti)
.venv-train\Scripts\python training\export_adapter.py --run thrones-adapter-0.1  # 3. LoRA -> GGUF, copy to models/
.venv-train\Scripts\python evals\eval_adapter.py --label base               # 4. evaluate base
.venv-train\Scripts\python evals\eval_adapter.py --label adapter --lora models\thrones-adapter-0.1.gguf
```

## Files

| File | Purpose |
|---|---|
| `build_dataset.py` | Builds `datasets/thrones_sft_v0.1.{train,heldout}.jsonl` and a manifest with row counts, licences and SHA-256. Uses the app's own system prompt and calculator so training matches inference. |
| `train_lora.py` | Unsloth bf16 LoRA (r=16, α=16, q/k/v/o/gate/up/down), loss on assistant tokens only, cosine LR 1e-4, 1 epoch. Saves the adapter, `config.json` (all hyper-parameters, base-weight hashes, dataset hash, library versions), `train_log.jsonl` and `summary.json`. |
| `export_adapter.py` | Converts the PEFT adapter to GGUF with llama.cpp's `convert_lora_to_gguf.py` and installs it into `models/`. |
| `../evals/eval_adapter.py` | Same inputs to base and base+adapter through llama.cpp: held-out tool use, held-out Hinglish (chrF), identity, and the 65-item regression sets. |

## Data rules

Only Apache-2.0 / MIT-compatible human-written datasets and examples generated by our own code. No outputs of Claude, Fable or any proprietary model. Every row carries `source`, `license`, `origin` and `transform` in its `meta` field.

## Known limits of v0.1

- The LoRA targets the 8 full-attention layers and all 32 MLP blocks; Qwen3.5's 24 linear-attention (Gated DeltaNet) projections are not adapted.
- Rows longer than 2,048 tokens are truncated (a handful; the system prompt alone is ~800 tokens).
- One epoch, one seed. Results are a single run, not an average.
